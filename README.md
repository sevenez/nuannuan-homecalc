# 暖暖家园计算器（无限暖暖 · 家园最大利润）

基于《无限暖暖-自动列出家园最大利润-可互动表格 v2.10.xlsx》算法移植的手机端应用。
同一套计算逻辑，两种使用方式：**PWA 网页版**（手机浏览器添加到主屏幕）和 **安卓 APK**（原生壳，离线可用）。

> 核心算法已逐格对拍验证：默认参数下「家具 Top10」的名称、排序与全部 11 项指标 10/10 完全一致；制作排程（轮次/每日上线/间隔/时间是否够）逐行一致。

## 二、数据分层设计

### 1. 本周填写（经常需要更新）

存于 `localStorage` 键 `nd_week_v1`，每周 Game 更新后可能需要修改：

| 字段 | 说明 |
|---|---|
| 周产能上限 | 本周家园币收益上限 |
| 本周已卖 | 已出售金额 |
| 剩余天数 | 本周剩余天数（同时驱动家具卡「排程」的时间判断） |
| 1.2倍订单 ×4 | 烹饪订单 / 小动物订单 / 家具订单（各是否享受 1.2 倍） |
| 想用掉的材料 | 材料筛选：优先消耗这些 |
| 要避开材料 | 材料筛选：排除含这些材料家具 |
| 不含灵感星标 | 是否排除灵感星标类家具 |
| 只算已有材料 | 材料是否齐全才参与排行 |

> **三类数据都会自动保存在本机**（`nd_home_v1` / `nd_week_v1` / `nd_sell_v1` 三个独立键），下次打开自动恢复，不用重填。
> 新的一周开始时：点计算页「**新的一周**」按钮，即可把已卖金额、剩余天数、1.2 倍选择清零（材料筛选偏好保留）。
> 也可在「我的」页分别「清空我的家园」/「清空本周设置」/「重置卖整勾选」。「导出配置」会同时打包三部分。

## 三、算法口径

```
售价   = ceil(基础价 × 甜食 × 建造加成 × (1.2倍订单 ? 1.2 : 1))
成本   = Σ ceil(材料数 ÷ 单次产量) × 材料单价        ← 单件制作成本
单品净赚 = 售价 − 成本
制作次数 = floor(剩余可赚 ÷ 单品净赚)
总净赚 = 单品净赚 × 制作次数
排程：
  轮数 = floor(制作次数 ÷ 工作台每轮产量)；余次 = 制作次数 − 每轮产量×轮数
  每日上线 = ceil((轮数 + (余次>0)) ÷ 剩余天数)；间隔 = 制作时间（<1小时按分钟，否则按小时向上取 1 位）
  时间判断 = (轮数 + (余次>0)) × 制作时间 ÷ 60 ÷ 24 > 剩余天数 ? 不够 : 还够
```

- **取整安全**：`Math.ceil(Math.round(x*1e6)/1e6)`，避免 `300×1.2×1.1 = 396.00000000000006` 被误取整为 397。
- **成本口径**：完全采用「成本」列（含作者手工填写的 0 成本副产品），不做任何推断——例如鱼精粹按鱼成本计，而副产精粹为 0。
- **树木/精粹派生价**：由种植等级套 `TIER` 公式推导。
- **两条售价链分别复刻**：查询页（家具&产物详细查看表口径）用材料**现价**（sheet6 的 FILTER 取价）；榜单/汇总链用**冻结价**（sheet11 旧价格表，共 66 处与现价不同）。本就是两条链，应用不做合并。
- 数据规模：**891 件家具、93 种材料、31 种烹饪、35 条隐藏产物、8 种饼干、44 种动物、121 项材料检索清单**。

## 四、卖整模块（独立 Tab）

把本周家园币卖到只剩零头时使用，按 blog 方案「**勾选即算**」。

### 模块构成

- **出售勾选**：
  - **本周 1.2 倍**：计算页设置的 1.2 倍物品（产物/动物/家具）直接以复选框呈现，默认全勾选，可取消（不卖某个 1.2 物品不影响计算页设置）；
  - **相应精粹（自动带出）**：勾选的 1.2 倍产物若对应精粹（名称 +「精粹」），自动带入方案，可单独取消；
  - **数量上限**：每行右侧可填「最多卖几个」（库存不够时用），留空 = 不限；输入即时存档并防抖重算方案，随勾选配置存档 / 导出，「重置卖整勾选」一并清空；
  - **+ 添加其他产物 / 精粹 / 树木 / 家具**：全屏弹层选择，全部 45 种产物、35 种精粹、8 种树木、826 件可售家具**全量可选**（虚拟滚动、拼音首字母搜索、分组过滤、价格排序），点选即入池。
- **凑整方案**：按凑整逻辑自动算每种卖多少个，恰好凑满本周剩余可赚金额 R；支持精确凑满 / 最接近差额、「其他解法」切换、一键复制；设了上限时方案严格不超过各产物上限（名称旁带 ≤N 徽标，复制文本附「上限 N」）。
- 勾选状态存于 `nd_sell_v1`（与家园/本周数据分开），「我的」页可一键重置。

### 凑整算法（参考 CSDN《无限暖暖家园园宝收购计算器》，推广到多种产物）

求解 `Σ(单价 × 数量) = R`（R = 周上限 − 本周已卖）的自然数解：

1. 勾选的产物全部参与（内部按单价降序取前 32 种，超出不计——blog 为 3 种，本实现不限 3 种）；
2. 一维 DP：`cnt[v] = 凑出恰好 v 的最少件数`，记录 predecessor 还原方案。无上限产物按无限背包升序松弛；带「数量上限」的产物按剩余类滑动窗口分层转移（有界背包，O(N)/种），件数严格不超上限；上限产物的转移只读「该层之前」的旧值，还原方案时切换到对应层快照回溯，避免同一产物被串出超上限的假链；
3. gcd 缩减：全部单价与 R 的公因子先约掉，缩小 DP 规模（60 万上限 × 32 种最坏约 26ms；32 种全设上限约 130ms）；
4. 目标：优先精确凑满；无精确解时取 ≤ R 的最接近值；同等金额下件数最少（优先卖贵的，减少交易次数）；
5. 「其他解法」：依次跳过最贵的 1/2/3 种产物重解（某种卖完了时用），懒计算、仅保留精确解；上限随池子一并参与。

实测：blog 两例复现（396/44/66→500000 无解差 6；476/1188/106→600000 精确 503+2+14 与 blog 一致）；300 组小规模随机暴力对拍（金额与件数）0 差异；上限版 500 组随机 + 构造例（同价不同上限 / 全上限 / gcd 缩放 / 无解 / 差额回退）与暴力枚举对拍 0 差异、上限全部被遵守；浏览器端到端复测全过（单/双上限精确最优、清空恢复、重置、导出含 caps、真实键入焦点保留）。

### 当前状态

- **全卖总销售 / 总利润 / 所需数量**：与凑整无关，已在「计算」页各榜单完整提供（卖家具总销售、卖家具总利润、做 N 个）。
- 库存不够的产物直接在勾选行填「数量上限」，方案自动不超上限；没填上限的也可按方案数量自行增减。单价自动含 1.2 倍 / 甜食加成。

1. **64 行缺失 CD/CE**（行673-736）：Excel 按 0 计 → 应用以 `z` 标记同样按 0 处理（sheet6 的 CI/CJ/CR/CP 均不含精粹/树售价，口径自洽）。

## 七、使用方式

### 方式 A：PWA（零安装，推荐先用这个体验）

需要一个本地静态服务器（`file://` 打开时 Service Worker 会被浏览器限制）：

```bash
cd /workspace/暖暖家园计算器/web
python3 -m http.server 8080
```

手机连同一 Wi-Fi，浏览器访问 `http://<电脑IP>:8080` → 菜单选「添加到主屏幕」→ 即可以全屏离线使用。
数据保存在手机浏览器 localStorage，重装/清缓存会丢失。

> **分享给别人**：把 `web/` 目录压缩发出即可，文件之间都是相对引用，解压后直接打开 `index.html` 就能用；若要保留 Service Worker 离线缓存，用本地静态服务器打开（`file://` 下 SW 会被浏览器禁用，但计算功能不受影响）。

### 方式 B：安卓 APK

安装包已就绪：**`release/暖暖家园计算器-1.210.6.57.apk`**（约 1.8 MB，正式签名版，Android 7.0+；应用内显示版本 v1.210.6.57）。

安装方式（二选一）：
- 手机打开「文件管理」找到该 APK，点击安装（需允许「安装未知来源应用」）；
- 或用电脑 adb：`adb install -r release/暖暖家园计算器-1.210.6.57.apk`。

数据保存在 App 的 WebView localStorage 中，卸载 App 即清除。
本包用个人签名密钥 `android/keystore/release.jks`（口令保存在本地 `android/keystore.properties`，**不随文档/仓库分发**）签名——密钥文件与口令自己留存即可，请勿随意外发；丢失后重新生成亦可，但换密钥后需先卸载再安装。

## 九、更新数据（游戏版本更新后）

数据全部来自 `data.js` 中的 `window.DB`，由提取脚本从 xlsx 解析。若游戏数值变动，需要重新从新版 xlsx 提取：

1. 用 `unzip -o 资料/算法来源表格.xlsx -d xlsx_extract/` 解包（表格存放在 `资料/`）；
2. 解析 `xl/worksheets/sheetN.xml` 的常量列与公式列（家具名 / 数量 / 成本 / 单次产量 / 精粹 / 树木）；
3. 重新生成 `data.js`，覆盖 `web/` 与 `android/app/src/main/assets/` 两处。

> 提取脚本逻辑见本目录下的 Python 脚本（如有保留）；无脚本时按上述列号重新解析即可。
